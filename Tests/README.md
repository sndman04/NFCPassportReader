# Passport protocol test corpus

Run the complete iOS suite and release checks from the repository root:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer scripts/release_check.sh
```

All fixtures are either published standards examples or generated fictitious documents. They contain no captured passport scans, personal photographs, real issuer private keys, or production trust anchors. Tests compare cryptographic buffers as booleans with fixed messages, so failures do not dump their contents. Do not replace these fixtures with document exports or attach raw scan data to a failing test.

## Fixture provenance

`NFCPassportReaderTests/Fixtures/icao9303.json` uses numeric examples from [ICAO Doc 9303 Part 11, eighth edition](https://www.icao.int/sites/default/files/publications/DocSeries/9303_p11_cons_en.pdf), consolidated PDF SHA-256 `953bd8998c254f14617675f7d138301afda65d55107f8e751baf50d7e9a3db86`:

- Appendix D.2–D.4: BAC derivation, authentication and protected EF.COM reads.
- Appendix G.1/G.2: ECDH/DH Generic Mapping conversations and intermediate results.
- Appendix H.1/H.2: Integrated Mapping component vectors. These start with the appendix's published password key and nonces; they do not invent a credential for that key.
- Appendix I.1: ECDH Chip Authentication Mapping conversation, encrypted proof and static public key.
- G.2 final response prints only dynamic-authentication data, including an optional authority reference. The fixture appends the normal-processing status stated in the accompanying table. Public points come from the complete APDU examples where a prose-table rendering has ambiguous spacing/duplication. DH unsigned integers and EC uncompressed points retain their specified wire encoding.
- The `password` fixture uses the synthetic string `123456` and independently calculated Python `hashlib` digests. The encoding/KDF is specified in Part 11 §9.7.3 Table 14 and [BSI TR-03110 Part 3](https://www.bsi.bund.de/SharedDocs/Downloads/EN/BSI/Publications/TechGuidelines/TR03110/BSI_TR-03110_Part-3-V2_2.pdf?__blob=publicationFile&v=1), A.2.3 Table 5 and D.2.1.4. Optional final PACE objects follow ICAO §4.4.4.2 and BSI B.1.

Only necessary factual test values are included, not the documents or third-party implementation code. No OpenPACE/GPL source has been copied.

`Fixtures/signed-passports.json` and the two test root PEM files are generated by `scripts/generate_synthetic_passport_fixtures.py` using Python `cryptography` (generation verified with 50.0.2). The generator independently constructs DER/CMS and signs it; it does not call this library. All private keys exist only during generation and are discarded. Certificates use fictitious test authority names, with a fixed 2020–2099 validity interval and a separate 2020–2021 expired case. Re-running generation changes random keys/signatures but preserves the scenarios. Tests use committed artifacts offline, so Python is not a test/build dependency. Never install these roots in a real application's master list.

`PassportTestSupport` is linked only into the test target. It imports published private/public pairs, verifies their mathematical consistency and preserves explicit mapped parameters. Its small C compatibility boundary uses the same scoped legacy OpenSSL accessors as `OpenSSLCompat`; deprecation suppression is restricted to that file. Test subclasses replace only entropy generation. Production entropy still uses the existing CSPRNG paths and has no public injection API. Fixtures are resources of the test bundle only.

## Limits and physical test matrix

This corpus is not a conformance certification or a country/issuer compatibility database. It does not exhaust every curve × mapping × cipher combination. [BSI TR-03105](https://www.bsi.bund.de/EN/Themen/Unternehmen-und-Organisationen/Standards-und-Zertifizierung/Technische-Richtlinien/TR-nach-Thema-sortiert/tr03105/TR-03105_node.html) is a useful source of additional conformance scenarios; running this suite does not claim to execute that certification plan.

Before a production release, test actual devices with PACE-capable and BAC-only test documents, interrupted GA, rejected selection, re-poll/reselection, RF loss, cancellation, timeout/backgrounding, incorrect access details, CA with large keys and large DG2 reads. Record only device/OS and document feature class, stage/event sequence and outcome. Do not record identity fields, APDU contents, credentials, cryptographic values or images.

Static data cannot prove chip reset behavior or CoreNFC delegate/RF behavior. Candidate tags remain candidates until the physical matrix is completed. Terminal Authentication, unsupported protocol versions, arbitrary proprietary extensions and issuer-specific failures are outside the claimed coverage.

## Diagnostic snapshot regression corpus

`DiagnosticSnapshotTests` exercises versioned snapshot delivery, success/failure scrubbing, both verifier orders, real CMS-to-manual fallback, independent signature/hash/trust failures, unsupported algorithms, parser metadata, partial hash coverage, AA/CA availability, native numeric codes/status words, early failure, timer expiry, cancellation, late responses, reentrant callbacks, consecutive attempts, bounded storage and sensitive-sentinel exclusion. Existing lifecycle/authentication suites remain acceptance and transport controls.

`Fixtures/diagnostic-passports.json` contains seven wholly synthetic CMS datasets produced by `scripts/generate_diagnostic_fixtures.py`, using Python cryptography independently of this reader. Both v0 and v1 are independently signed and verified before packaging. `testIndependentV0AndV1SignaturesPassBothVerifiersAndBothParse` replaces the rc.5 rejection regression: both original signed fixtures must now pass both real signature implementations, parsing, hash comparison and `.notaryStrict`. Their bytes and trust root are unchanged from rc.5, including the actual signed v1 content. The generic rsaEncryption case now passes manual verification directly; the independent PSS content-hash variation in the new signature corpus exercises actual CMS-to-manual fallback. Other cases have unknown digest/signature identifiers, an invalid hash length, or an invalid LDS root tag. An additional independent ECDSA AA key/challenge/response fixture covers successful and tampered anti-cloning verification without retaining its bytes in snapshots. `diagnostic-csca.pem` is a generated **test-only** authority. Private keys are never saved. No real passport captures are used.

`Fixtures/sod-version-passports.json` adds 78 independently signed cases generated by `scripts/generate_sod_version_fixtures.py` with its own test-only `sod-version-csca.pem`. The 22 positive cases cover v0/v1 × SHA-1/224/256/384/512 × absent/NULL parameters, other valid version strings, and sixteen hash entries. The 56 rejected cases cover missing/extra/reordered/truncated version fields, invalid string tags/lengths/characters/ranges, unsupported versions (including inner v3 and integers beyond machine width), unsupported/malformed digests, noncanonical DER and invalid hash lists. Even malformed content has a valid independent signature. Every case runs manual-first and CMS-first; failures are checked after lifecycle scrubbing. Separate v1 mutations verify signature, signed-content and hash failures; missing/unrelated trust roots still fail trusted policy. Every truncated prefix of the original v0/v1 content is rejected. Older one-entry synthetic parser fixtures now include a second unread hash to satisfy the profile while preserving their original test purpose.

Rules and source clauses are recorded in [the SOD v1 migration note](../MIGRATION_NOTARY.md#sod-version-1-compatibility-privacy6-rc6). Generators persist only synthetic signed/public artifacts; original regression fixtures must not be regenerated when extending this corpus.

Regeneration requires Python `cryptography` (available in the bundled workspace runtime in this environment); tests need only committed fixtures, not Python or network access. Regeneration intentionally creates new keys/certificates. Tests avoid printing contents and verify the encoded diagnostic snapshot excludes synthetic identity strings, complete DER/content/group encodings, certificate markers and all actual group hash values. Physical NFC callback/RF behavior still requires device testing.

The [standards inventory](../STANDARDS_COVERAGE.md) records exact source clauses, capabilities, resource bounds and exclusions. Do not use an implementation allowlist as the only acceptance oracle. A test expecting a valid in-scope standard input to fail is a known-defect reproducer, not compatibility acceptance.

Generators `generate_signature_profiles.py`, `generate_face_profiles.py`, `generate_pace_parameter_profiles.py`, `generate_active_authentication_profiles.py` and `generate_revocation_profiles.py` save only synthetic signed/public artifacts. They never save private keys. Cryptography signs/verifies inputs independently of reader code; OpenSSL CLI exports public explicit parameters and Pillow creates non-person images. No real document, biometric photograph or production trust anchor is included. Original rc.5 signed fixtures remain unchanged.
